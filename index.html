How Credential Issuance Works

ForgeGuard issues Verified Audit Badges — a structured, verifiable process controlled by ForgeGuard after a real audit.

01

Submit for Audit

Submit your smart contract to ForgeGuard's AI audit pipeline for security analysis.

02

ForgeGuard Audits & Verifies

ForgeGuard completes the audit, generates the report, computes the SHA-256 report hash, and signs the result with a verification signature.

03

Assign Your HACD

The audited project provides a specific HACD name they own to anchor the badge, plus HAC for the stack cost and network fee.

04

ForgeGuard Issues the Badge

ForgeGuard initiates the Stack transaction with the full audit payload — contract address, report hash, and verification signature — forming the badge on your HACD.

05

Verify On-Chain

Your Verified Audit Badge is now permanently formed on your HACD. Anyone can verify the credential by checking the payload on-chain.

Frequently Asked Questions

Can anyone stack a ForgeGuard badge?

+

No. ForgeGuard badges are verified credentials issued only after ForgeGuard completes a real security audit. Random HACD holders cannot self-form badges. Only ForgeGuard can initiate badge formation.

What data is embedded in each badge?

+

Every badge contains: audited project name, contract address, blockchain, report hash (SHA-256), audit date, audit scope, ForgeGuard verification signature, and the HACD name it's anchored to.

How can I verify a badge is real?

+

Check the HACD on-chain. The badge payload includes ForgeGuard's verification signature and the report hash. You can independently verify both without trusting ForgeGuard's servers.

Do I need HACD and HAC?

+

Yes. Each ForgeGuard badge is anchored to a specific HACD unit. The audited project needs at least 1 HACD to receive 1 badge. HAC is needed for the stack cost and network fee.

Does a ForgeGuard badge mean my project is completely safe?

+

No. The ForgeGuard AI audit pipeline identifies known vulnerability patterns. No audit can guarantee the complete absence of security issues. A ForgeGuard badge verifies that the audit process was completed, not that the code is flawless.

Is this a public token launch?

+

No. ForgeGuard operates as a verified credential issuance model. Badges are created only after ForgeGuard completes a real audit. ForgeGuard controls badge issuance — this is not an open formation where anyone can stack.

What happens if I unstack my badge?

+

Based on our removal logic, unstacking permanently destroys the badge. The HACD is freed, but the credential is gone. This preserves credential integrity.

Is this an investment product?

+

No. ForgeGuard badges are functional security credentials. They are not investment products, securities, or financial instruments. No profit, return, yield, or resale value is assured or promised.
